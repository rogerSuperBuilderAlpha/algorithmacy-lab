## What it argues

"Interface agents are computer programs that employ Artificial Intelligence techniques to provide active assistance to a user with computer-based tasks. Agents radically change the current user experience, through the metaphor that an agent can act as a personal assistant. The agent acquires its competence by learning from the user as well as from agents assisting other users" (abstract). Against direct manipulation, which "requires the user to initiate all tasks explicitly and to monitor all events," Maes proposes "indirect management," in which "the user is engaged in a cooperative process in which human and computer agents both initiate communication, monitor events and perform tasks" ("What can agents do for you?"). Agents "perform tasks on the user's behalf," "help different users collaborate," and "monitor events and procedures." Two problems govern the design: "competence: how does an agent acquire the knowledge it needs...?" and "trust: how can we guarantee that the user feels comfortable delegating tasks to an agent?" ("Approaches to building agents"). Her answer is machine learning from four sources — watching "over the shoulder" of the user, direct and indirect feedback, explicit examples, and asking "for advice from agents that assist other users with the same task" — on the model of a new personal assistant who "learns... by learning from other more experienced assistants within the organization" ("Training a Personal Digital Assistant"). Trust is built gradually: "the user is also given time to gradually build up a model of how the agent makes decisions," and the agent explains itself "in terms of past examples," e.g. "because assistant Y to person Z also performs tasks that way, and you and Z seem to share work habits." Four prototypes: Maxims (email; a "do-it" threshold above which "the agent autonomously takes the action on behalf of the user" and writes a report, a "tell-me" threshold below which it only suggests; "The user is responsible for setting" both), a meeting-scheduling agent that can "negotiate meeting times," NewT (Usenet filtering; 12 test users), and Ringo (music recommendation by "social filtering" among agents whose users' tastes correlate). Maxims agents "gradually learn which other agents are trustworthy sources of information." The closing questions include: "How can we guarantee the user's privacy, especially if agents communicate with one another about their users?... Most importantly, from a legal standpoint, should a user be held responsible for his or her agents' actions and transactions?" ("Discussion").

## Relation to the argument

RQ8, the origin of the user-agent idea in HCI and therefore the first anchor for Principle I. Sorted: **counter-delegation proper in embryo** — the agent acts for its user, inside the user's tasks, in real time, with delegation thresholds the user sets; and Maes's agents already meet *other people's agents* (meeting negotiation, Ringo's correlated agents, Maxims asking peers). What is absent is the adversary: every counterpart agent in Maes is a colleague's assistant in the same lab, and the "community" is cooperative, so competence flows between agents rather than being contested by them. The construct's counter-agent inherits her two problems — competence and trust — and adds a third she never faces: the party the agent must read is an intermediary that "pursues an objective neither set." Three specific uses. Her "do-it"/"tell-me" thresholds are a 1994 design for the autonomy boundary any counter-agent needs. Her explanation-by-precedent ("because this situation is similar to...") is the client-side analogue of the explanation the intermediary will not give. And her closing legal question — is a user responsible for her agent's transactions? — is the liability problem Principle I must answer for a counter-agent that contests on one's behalf. CUTS AGAINST the paper's implicit assumption that a user-side agent is a new proposal; the lineage is thirty years old and its failure mode (agents that never became adversarial because they were never deployed against a hostile intermediary) is instructive.

## Caution

Author-hosted HTML from a 1999 archive capture, not the CACM pages; no page numbers, no figures, and possible small divergences from the printed text — check any quotation against the PDF before print. The "user tests" are described in a few sentences each ("very encouraging," "Users reported that they felt comfortable delegating tasks to the agents") with no numbers beyond "12 users" for NewT. All four systems are lab prototypes at the MIT Media Lab, and the paper's framing of trust is the user's comfort, not the agent's loyalty. Nothing in the paper concerns platforms, matching, or an intermediary with interests of its own.
