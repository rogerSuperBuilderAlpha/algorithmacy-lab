# Argument: design for the third party

[DRAFTED by Claude, 26 Oct 2026. Angle sharpened against the OT paper (see FLAGS 2).]

**P1.** When an IS artifact evaluates two people and binds both, each person needs to interpret its verdicts, address the other person through it, and track its changes. Transparency about the model does not supply any of these, because the opacity is intrinsic and the parties need to know whose input moved the verdict, not how the model works.
- *Sources:*
  - `lima_pdw/literature/cards/burrell2016.md` (abstract depth)
  - `dxd_foundation/literature/library/kroll2021outlining.md` (p. 4: disclosure is not traceability)
  - `lima_pdw/literature/cards/rahman2021.md` (p. 976: the parties' shares are unspecified)

**P2.** Design research offers contestability and traceability as system features, but it models one decision subject. Users told that an evaluating filter exists start writing for it as an audience.
- *Sources:*
  - `dxd_foundation/literature/library/alfrink2023contestable.md` (p. 614)
  - `dxd_foundation/literature/library/lyons2021conceptualising.md` (p. 15: contestation imagined as post-hoc appeal)
  - `dxd_foundation/literature/library/eslami2019user.md` (pp. 11–12)

**C.** IS artifacts that stand between two people need three design properties keyed to the three practices. The first is provenance cues, which show which party's input moved a verdict. The second is a dual address, which shows each sender what the evaluator will read and what the counterpart will read. The third is change notice, which logs and announces rule updates to both parties. Each property can be stated as a testable design proposition without promising transparency of the model.
