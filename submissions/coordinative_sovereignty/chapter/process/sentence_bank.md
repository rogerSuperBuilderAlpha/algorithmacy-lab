# Sentence bank and per-sentence drafting protocol — 2026-08-23

Companion to `STYLE_SPEC.md`. The spec says what a conforming sentence looks like; this file supplies the comparison targets and the workflow. Every sentence in the draft is written against a model sentence with the same function, and no sentence enters the manuscript without its function, its exemplar, and its gate result recorded during drafting.

## 1. The function taxonomy

Twenty-four sentence functions cover the chapter. F1 scene-setting opener with a dated, named actor. F2 full thesis statement. F3 stakes. F4 enumeration announcement. F5 concept stipulation or coinage. F6 paradigm-case introduction. F7 borrowed definition with page pin. F8 claim opening a paragraph. F9 empirical support with terminal citation. F10 mechanism explanation. F11 question hinge (rationed: two per chapter). F12 answer following the hinge. F13 objection introduction in the impersonal modal frame. F14 objection stated in the indicative at full strength. F15 diagnosis return. F16 concede-then-contain return. F17 bridge between sections. F18 normative-payoff paragraph close. F19 institutional-remedy sentence. F20 conclusion recap. F21 scope limitation. F22 short pivot (clarifying denial, imperative case-introduction, or verdict). F23 contrast construction with parallel clauses. F24 positioning sentence (what a neighboring construct does and what this one does that it does not).

## 3. The per-sentence workflow

Drafting proceeds sentence by sentence, and each sentence is recorded in a three-column ledger while its section is open: the sentence, its function code, its gate result with the exemplar it was checked against. The steps for one sentence. First, name the function before writing a word; if no function from the taxonomy fits, the sentence is probably filler and is not written. Second, retrieve the exemplar for that function and reread it. Third, draft the sentence imitating the exemplar's skeleton: its subject position, clause order, connective, and citation placement, with the houseification note applied. Fourth, run the gate (G1–G16 from STYLE_SPEC) on the drafted sentence. Fifth, run the comparison: subject type matches the exemplar (concrete actor or defined construct), length within the exemplar's band (±40 percent), connective equivalent, citation placed as the exemplar places it, and no element present that the exemplar's function does not license (a hedge in a claim, a citation in a coinage, an enumeration in a pivot). A sentence that fails either the gate or the comparison is rewritten before the next sentence is drafted; failures are logged, not silently fixed, so patterns of failure surface. The ledger for each section is saved beside the draft (`drafting_ledgers/section_N.md`) and is the artifact the sentence-read reviewer checks in the QA protocol's second pass.

Slop, operationally, is any sentence whose function cannot be named, whose exemplar comparison fails on two or more axes, or that repeats a skeleton already used twice. The ledger makes all three visible.

## 5. Scale plan

Drafting runs section by section in OUTLINE_v2 order, one ledger per section, gate enforced at draft time rather than after. The reviewer pass (a second reader over the ledger, per STYLE_SPEC §4) runs before a section closes. Aytac remains the argument-section comparator, Cutolo and Kenney the applied-section comparator; where a function has no Aytac exemplar the Stark corpus and the Rawls skill supply it, in that order. The bank is closed: no new exemplars enter mid-draft without being added to this file first, so the standard cannot drift while the drafting is under way.
