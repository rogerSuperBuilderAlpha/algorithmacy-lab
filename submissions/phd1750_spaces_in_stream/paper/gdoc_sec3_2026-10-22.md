### **3. Streaming in Contemporary Human-Computer Interaction, Automation, and Large Language Model Reliance Accounts**

If critical reading requires stable landing points, event boundaries, and a spatial surface that can be probed at will (Section 2), contemporary interfaces may initially appear to address these requirements. Systems increasingly interrupt the information stream, ranging from agentic environments that pause for plan approvals and command authorizations to research prototypes such as WaitGPT (Xie et al., 2024), which parse real-time output into visual nodes for monitoring and steering. However, these interruptions remain confined within a dyadic structure specified for the platform's intent: because the system itself places, words, and ranks these cues, the user merely selects from a predefined menu rather than identifying where the underlying computation commits to action. As Johnson (2000, pp. 608, 610) notes regarding historical writing systems, reading cultures adopt only the aids their prevailing practices require and resist those they do not. The current culture of observing artificial intelligence performance readily adopts cues for approval—such as permission prompts, status indicators, and multiple-choice options—because these maintain the existing reading system without disruption. This resists, and systematically omits, the structural spaces needed to interrogate an intermediary’s latent commitments. Interfaces that multiply these system-authored cues produce readers of an automated stream (literacy), rather than supervisors capable of identifying and contesting latent algorithmic choices (algorithmacy). This phenomenon constitutes the literacy trap of Section 1 in its current form: reducing human agency to selecting among system-curated alternatives while leaving the triadic, co-optive process unexamined. The platforms solve an optimization problem, keeping the user moving through the task, and leave the structural one, where the stream binds the user's intent, unaddressed. To analyze how current paradigms perpetuate this trap, this section begins with a case study tracing how Claude Code stages decisions in practice (3.1). Subsequently, four adjacent research traditions are evaluated—streaming and pacing (3.2), automation supervision (3.3), language-model overreliance and friction (3.4), and ocular gaze as a metric of oversight (3.5)—before synthesizing their shared commitments within a comparative framework (3.6).

#### 3.1. Case Study: Staging of Decision Points in Claude Code

To examine how decision points are structured on contemporary interaction surfaces, this section analyzes Claude Code, a terminal-based programming agent (Anthropic, 2026b). Although this system did not originate staged decision points, earlier implementations appeared in commercial tools such as GitHub Copilot Workspace and OpenAI Deep Research, as well as research prototypes like WaitGPT (Xie et al., 2024); Claude Code offers an unusually transparent empirical record. Its public version history, dated changelog, and open documentation let users trace, from primary sources, the precise introduction of intermediate checkpoints, the wording of their options, and shifts in the platform's interaction model over time. In interactive (“Plan”) mode, the user observes an advancing stream in which natural-language reasoning alternates with automated tool calls, including file edits, codebase searches, and bash commands. By default, this stream does not pause unless the user presses Escape to abort the active turn mid-execution (Anthropic, 2026a). If an operator types an instruction while the agent is running, the interface queues the message rather than interrupting the turn, requiring the user to wait for a system-determined breakpoint. As outlined in Section 2, this architecture imposes an externally paced pursuit task on the human operator: the text continuously scrolls, previous terminal reasoning drifts off the display, and the cognitive burden of identifying the precise operational juncture for interruption rests entirely on the supervisor's continuous, cognitively taxing vigilance.

Between 2025 and 2026, the platform implemented a series of explicit pause points, delineating a clear developmental trajectory. Initially, the system introduced intermediate decision junctures, which it later removed systematically. The first phase established structural landmarks to guide execution: an explicit task list designed to maintain agent focus was introduced in April 2025 (v0.2.93), followed by a dedicated plan mode, first documented in June 2025 (v1.0.33; Anthropic, 2026b). By late 2025, cognitive labor was partitioned across models, with Opus responsible for plan formulation and Sonnet for code execution (v1.0.77, August 2025). Additional features included discrete state checkpoints via the /rewind command (v2.0.0, September 2025) and increased solicitation of clarifying input during planning (v2.0.21, October 2025). Each intervention remained narrowly defined. Until July 2026, unanswered user queries would automatically time out and resume execution independently (v2.1.200; Anthropic, 2026b). In late 2026, the interface began to retract these interventions: in August 2026, Bash execution prompts included a "Yes, and switch to auto mode" option (v2.1.247), and by September 2026, auto mode became the default starting state for all plans (v2.1.283; Anthropic, 2026a). Over sixteen months, the interface evolved from an uninterrupted stream to a structured sequence of pauses, and ultimately to an autonomous mode designed to eliminate the interruptions it had previously introduced.

The structural logic of these breakpoints is evident in the interface’s expectations for user decision-making. When the agent pauses for plan approval, the user encounters a terminal menu with "Yes, and use auto mode" as the primary option, followed by "Yes, manually approve edits" and "No, keep planning" (Anthropic, 2026a). Selecting the first option accepts the proposed sequence and suppresses the granular checkpoints that would otherwise occur during execution. Notably, the plan is already constrained: as of December 2025, system instructions for plan generation directed the model to "Include only your recommended approach, not all alternatives" (Ronacher, 2025). The model collapses the latent decision space, including competing architectural paths, rejected libraries, and unexamined trade-offs, before rendering any text on screen. When the agent requests clarification mid-task, it presents a multiple-choice prompt written entirely by the model, limiting the user to system-generated options or a custom response via an "Other" entry (Anthropic, 2026b). The platform maintains a formal boundary of human oversight: permission prompts and plan approvals "never auto-resolve on idle," ensuring the agent cannot proceed past a staged gate without explicit user input (Anthropic, 2026a). However, the system frames this residual friction as an operational cost to minimize, explicitly presenting auto mode as a way to reduce "prompt fatigue" and encouraging Claude to keep working without pausing for clarifying questions (Anthropic, 2026a). An automated classifier, rather than the human operator, evaluates execution risks, reducing the user's role to approving a trajectory whose underlying alternatives remain obscured.

Viewed through Johnson's (2000) historical framework, these interface mechanisms illustrate how contemporary tools reinforce passive reading practices rather than promoting algorithmic oversight. Johnson frames reading as a "sociocultural system in which the individual participates" (pp. 602–603), rather than as an isolated cognitive act. Within Claude Code, the interaction model constructs a specific system: a solitary expert developer observes an automated agent performing code generation. This arrangement closely parallels classical bookrolls, which scribes formatted as unpunctuated scripts to be "played" like musical scores, assigning pacing, pauses, and rhetorical inflection entirely to the "reader-performer" (Johnson, 2000, p. 620). The token stream is similarly presented as a performance; the user observes the agent’s execution in real time and responds only when the system reaches an operational breakpoint. Dialogs, multiple-choice prompts, and status indicators that interrupt this stream serve as performance cues, not as structural spaces. These cues are analogous to marginal accents or modern tone markers that reading cultures employ to sustain existing practices without modifying their material architecture (Johnson, 2000, p. 608). They signal to the watcher when to approve, but they do not offer a fixed spatial reference for inspecting, reviewing, or reconsidering prior commitments. This performance logic extends to state restoration: just as excerpts of an ancient roll could be sequentially "replayed."

In contrast, "nothing in the ancient bookroll was designed to facilitate retrieval in any other way" (Johnson, 2000, p. 620). Claude Code’s /rewind command indexes historical checkpoints exclusively to the user’s sequential prompts—one entry per prompt sent (Anthropic, 2026b)—enabling chronological replay by turn rather than targeted retrieval based on the agent’s internal decision spaces. Similar to ancient technical texts that functioned as "closed systems" written strictly specialist-to-specialist (Johnson, 2000, p. 612), Claude Code’s menus presuppose an expert user who understands each option; for non-experts, selecting from system-authored choices does not replace the ability to locate where the stream commits them. The platform provides cues for an unfolding performance but lacks spaces for user governance. Its development trajectory in late 2026 further shows how vendors can readily remove even these cues to increase speed.

This staged interaction model is not unique to Claude Code, nor did this platform originate the pattern. Previous commercial and research systems introduced similar intermediate junctures. For example, GitHub Copilot Workspace structured agentic development around two explicit steering moments: editing the initial task specification and subsequently modifying the proposed execution plan. OpenAI's Deep Research pauses before initiating long-horizon information retrieval to solicit clarifying user guidance. Concurrently, research prototypes such as WaitGPT (Xie et al., 2024) and Magentic-UI (Mozannar et al., 2025) have investigated on-the-fly task partitioning. However, industry implementations are diverging, with some contemporary developer tools eliminating planning checkpoints entirely (Ronacher, 2025). The critical ergonomic question these designs raise does not require attributing commercial motives or deliberate engagement maximization to platform architects. Instead, following Stark and Vanden Broeck's (2024) analysis of platform coordination, evaluate the issue by its structural effect on agency and choice architecture. Regardless of vendor intent, when an interface determines decision points, defines available alternatives, and ranks them, it exercises coordinative co-optation. The user's supervisory authority is limited to ratifying the system's operational momentum by selecting among options the intermediary pre-filters. The vendor's stated rationales, such as curbing "prompt fatigue" and deploying automated classifier "nudges" to bypass clarifying pauses (Anthropic, 2026a), document this structural consequence within engineering discourse. By treating user intervention as operational friction to minimize rather than an essential supervisory affordance, contemporary front-ends systematically sacrifice the structural conditions of algorithmic agency for uninterrupted execution.

#### 3.2. Streaming and Pacing

Research on streaming and pacing in conversational interfaces primarily frames temporal delivery as an engineering throughput issue, a social presence concern, or a reading-comfort issue. Modulating response latency or simulating conversational typing consistently alters user perception: simulated sentence typing delays increase perceived competence, trustworthiness, and persuasiveness without affecting perceived task effectiveness (Bhat, 2025). Initial response latency leads users to attribute "AI deliberation" to the system (Tan et al., 2026) and alters perceived social presence (Gnewuch et al., 2022). Nevertheless, evidence that dynamic text delivery impairs supervisory discernment remains limited and confounded. Anderl et al. (2024) found that presenting information as a screencast of a typing chatbot reduced participants' ability to distinguish accurate from inaccurate claims in one experiment (p=.029), but not in a preceding trial (p=.212). Because the typing animation was embedded in a chatbot interface, dynamic pacing combined with conversational framing made it impossible to determine whether the impairment resulted from the kinetic display or the conversational medium. When systems research addresses the token stream directly, it conceptualizes temporal delivery as aggregate velocity. Infrastructure frameworks calibrate token emission against estimated human consumption baselines. For example, Andes estimates silent reading at approximately 4.8 tokens per second to optimize serving schedules (Liu et al., 2024). Xiao and Yang (2025) measure 99th-percentile comfortable reading speeds—11.97 words per second for complex text and 21.20 for easy prose—to throttle commercial APIs that output at more than double those rates. This rate-based perspective aligns with earlier psycholinguistic research on moving displays. Smoothly scrolling text can support literal comprehension comparable to rapid serial visual presentation (Kang & Muter, 1989). However, continuous movement disrupts higher-level inferential comprehension and makes it significantly harder to return to previously encountered text (Harvey & Walker, 2018). User-manipulated scrolling yields fewer, more dispersed look-backs than discrete paging (Haverkamp et al., 2023).023).

Importantly, this literature treats pacing as the digital equivalent of poetic meter, conceptualizing it as a continuous property of system performance. Whether adjusting server throughput or measuring comfortable reading velocity, existing research varies only the speed or smoothness of token delivery. It does not address where in a forming response the stream should pause, who sets that boundary, or how a reader might identify a latent operational commitment in natural-language prose. By framing delivery solely as a question of rate, pacing research neglects the stream's internal structure and offers users no structural affordance beyond a basic abort command.

#### 3.3. Automation Supervision and Trust

Unlike research on reading or interface pacing, human-factors scholarship on automation conceptualizes the human operator as a supervisor monitoring an autonomous system (Endsley, 2017; Parasuraman & Manzey, 2010). Within this framework, supervisory failures result from breakdowns in attentional allocation under multi-task workload (Parasuraman & Manzey, 2010). In their foundational synthesis, Parasuraman and Manzey introduced the concept of "looking-but-not-seeing" to explain commission errors, noting that operators often follow faulty automated advice even after reviewing all necessary external information. In a systematic review of automation bias literature, Goddard et al. (2012) identified workload, task complexity, and time constraints as key environmental mediators of complacency. They highlighted the physical screen position of advice and the provision of raw data instead of canned recommendations as primary design mitigators.

Presenting system output as an explicit recommendation fundamentally changes user scrutiny. In simulated control tasks, automated recommendations improve overall task accuracy but slightly reduce an operator's ability to distinguish between accurate and inaccurate system guidance (Gegoff et al., 2025). Allowing operators to control transparency does not resolve this bias. When operators can adjust information detail, they rarely select high transparency, and mandatory high transparency increases agreement bias without improving detection of faulty advice (Tatasciore et al., 2026). In interactive agent workflows, oversight often fails due to temporal coordination issues. Chen et al. (2026) found that more than half of supervisory failures resulted from timing mismatches, where operational risks appeared before or without an explicit opportunity for user intervention. Chen and colleagues concluded that effective oversight requires aligning authority, timing, and attention to "trigger judgment before a consequential transition." Over time, operators adapt by learning the system's operational "boundary conditions" and stop treating automation as a general advisor (Lamb et al., 2026; Lee & See, 2004). However, as system autonomy and reliability increase, situation awareness systematically declines (Endsley, 2017). This creates an automation conundrum relevant to generative supervision: the more reliable and seamless the automated execution, the less prepared the human supervisor is to reassert control when anomalies occur.

In light of the central question of algorithmacy—who sets the decision point, and what actions the user can take—this literature reveals a common structural assumption: the designer sets the decision point in advance on a static display. Whether through alert placement (Goddard et al., 2012), prescribed transparency toggles (Tatasciore et al., 2026), or recommendations to pause before consequential state transitions (Chen et al., 2026), the interface dictates where the human evaluates the system. The operator responds to engineer-authored cues by accepting, rejecting, or modifying a discrete proposal. This tradition overlooks continuity. Automation research typically models machine assistance as a sequence of isolated events, such as alarms, diagnostic labels, or recommendation modals. In contrast, a streamed generative response is a continuous temporal process in which moments requiring critical judgment arise within the evolving language. When platforms suppress intermediate prompts to reduce "prompt fatigue," as seen in Claude Code's shift toward a default auto mode (§3.1), they manifest Endsley's (2017) conundrum on the screen: execution speed is increased, but supervisors are deprived of structural means to identify where the advancing stream aligns with their intent.

#### 3.4. Overreliance on Large Language Models: Fluency and Cognitive Friction

Research on human interaction with large language models identifies supervisory failure as stemming from the persuasive nature of textual fluency and the cognitive economics of user effort. Fluent explanations consistently increase reliance on model outputs, regardless of the accuracy of the underlying assertions (Kim et al., 2025). When models provide persuasive rationales, users systematically overestimate system accuracy; longer explanations further increase user confidence without improving correctness (Steyvers et al., 2025). At the model level, larger, more instructable architectures generate plausible yet deceptive errors more often (Zhou et al., 2024), while preference optimization can make justifications for false answers convincing without improving error verifiability (X. Zhu et al., 2026, preprint). This uncritical reliance reflects a rational cognitive trade-off: users weigh the substantial effort required to verify complex text against the low-cost heuristic of accepting fluent prose (Vasconcelos et al., 2023). As a result, users often resort to coarse scanning and indiscriminate copying because interfaces rarely support efficient verification (Fok & Weld, 2024; Liu et al., 2026). To counteract this passive compliance, human-factors researchers introduce cognitive friction. Cognitive forcing functions, such as mandatory waiting periods before advice appears or prompts to examine underlying assumptions, can reduce overreliance on erroneous recommendations, though often at the expense of user satisfaction (Buçinca et al., 2021; Ghosh et al., 2026, preprint). Peripheral obstacles, including selective access barriers (Collins et al., 2024, preprint) or preparatory microboundaries (Arun & Fischer, 2026; Cox et al., 2016), frequently increase perceived workload without reliably improving critical evaluation.

Additionally, prompting users to reflect can provoke resistance from operators who prefer direct answers over artificial questioning (Forshaw et al., 2026). When interventions operate directly on model output, they alter its semantic content, such as by injecting first-person expressions of uncertainty (Kim et al., 2024) or framing explanations as questions (Danry et al., 2023), or by modifying generation at the model level through concept suppression (Disley & Khan, 2026).

When evaluated in relation to the central question of algorithmacy—namely, who determines the decision point and what actions the user takes—the friction literature reveals a distinct structural boundary. Friction typically appears either before an interaction begins, at the threshold of model access, or within the model's weights. When interventions appear within generated text, they alter the linguistic substance of the system's output. However, none of these approaches identifies the moments when an unchanged response requires critical judgment. Interface designers uniformly set decision points, or automated confidence heuristics trigger them, causing users to respond to system-imposed obstacles rather than develop the ability to identify latent commitments independently. Moreover, this research tradition directly conflicts with commercial interface development. Although empirical findings indicate that unreflective fluency undermines supervisory vigilance and that cognitive forcing is necessary to maintain critical scrutiny, contemporary platforms treat friction as "prompt fatigue" to be eliminated. For example, as seen in Claude Code's transition to default auto mode (§3.1), vendors address user friction by removing intermediate checkpoints and assigning risk classification to secondary models. By moving obstacles outside the text while eliminating remaining pauses, both approaches produce an uninterrupted generative stream, trapping the operator in a literacy trap that equates syntactic fluency with verified intent.

#### 3.5. Gaze Allocation as an Ambiguous Metric for Oversight

In empirical evaluations of generative and automated systems, researchers often rely on eye-tracking metrics grounded in the strong eye–mind hypothesis, which assumes that fixational dwell, saccadic targeting, and visual transitions reliably proxy cognitive scrutiny and supervisory engagement. Applied to streaming text, eye tracking shows that dynamic delivery disrupts visual exploration: continuous token generation increases overall fixation counts, extends cumulative gaze duration, and focuses initial fixations almost exclusively on the leading edge where new characters appear (Park & Lee, 2024). However, across interactive interfaces, ocular fixation often diverges from supervisory discernment and critical verification. Modifying the layout of conversational outputs changes how quickly users first fixate on source attributions, but longer gaze dwell on those citations does not predict whether users calibrate their trust or critically evaluate model claims (Cho & Lim, 2026). Furthermore, as sensorimotor psychophysics has established, visual gaze reflects low-level alerting and stimulus-driven capture as much as active deliberation. An operator may look directly at an anomalous or erroneous token without cognitively registering the mistake (O'Regan & Noë, 2001; Parasuraman & Manzey, 2010).

Regarding the central question of algorithmic agency, gaze tracking reveals a significant analytical limitation: it records foveal direction. Still, it cannot determine whether the user identified an operational decision space or simply followed a system-generated visual cue. In an unmarked token stream, the clustering of fixations at the advancing edge reflects the oculomotor system's response to successive abrupt onsets (Section 2.3), rather than intentional supervisory navigation. Even when an interface pauses to display an interactive dialog or permission prompt, gaze dwell on that menu only confirms that the user is reading the model-generated text; it does not indicate that the operator has recognized the latent alternatives or architectural commitments that the system resolved before the prompt appeared. Gaze measures the user's participation in the interface's reading process but cannot assess whether the user has identified where the computation constrains their intent. By equating ocular inspection with supervisory control, current evaluation paradigms remain limited to a literacy-based reading model, which obscures the structural distinction between reading an automated output and identifying its latent decision spaces.

### **3.6. Synthesis: The Missing Variable in Current Accounts**

Across these four research traditions and contemporary agentic platforms, a consistent structural paradigm is evident: supervisory agency is conceptualized as a reaction to system-authored representations. Pacing research adjusts delivery speed without changing the stream's internal structure (3.2). Human-factors models of automation conceptualize machine assistance as discrete advice presented on static displays, requiring operators to respond to boundaries established by designers (3.3). Cognitive friction interventions introduce obstacles at the periphery of model access or alter lexical phrasing, yet the structural progression of an unchanged response remains uninterrupted (3.4). Gaze tracking quantifies ocular pursuit along kinetic onsets, conflating fixational dwell with supervisory scrutiny (3.5). Commercial agents that implement intermediate pause points similarly restrict the operator to selecting among system-authored options at moments determined by the platform's operational flow (3.1). In all these paradigms, the human operator is cast as a reader who decodes, waits, or chooses. None of these approaches provides a structural affordance that enables the user to identify where the unfolding computation commits their intent.

When existing front-ends intervene, they provide menus that require literacy, such as reading system-authored text and selecting among curated alternatives. These interfaces lack the visual landmarks necessary for algorithmacy, specifically, for identifying where an opaque, optimizing intermediary makes state-altering commitments during an unfolding performance.
