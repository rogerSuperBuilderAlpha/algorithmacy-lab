# Aneesh, A. (2009). Global Labor: Algocratic Modes of Organization. *Sociological Theory*, 27(4), 347–370.

**Identifier:** https://doi.org/10.1111/j.1467-9558.2009.01352.x · **Read depth:** adapted_from_verified_card · **Source-tier:** primary_journal · **Evidence basis:** reused_verification — verified previously in `dissertation/research/library/aneesh2009.md` from a full-text read of the article (pp. 347–370); adapted here · **Relation last checked:** 2026-09-15

## What it argues

Aneesh names a third mode of governance, algocracy — rule of the code — and sets it beside bureaucracy and the market. The empirical base is ethnographic: globally distributed software work and call centers in India serving U.S. firms (twelve months across twenty firms, 1999–2000; call-center observation, 2004–2005; over fifty hours of interviews). Such work cannot be governed bureaucratically, because no shared legal-rational authority spans the nations involved, nor by the market alone, because it is collaborative work on a shared deadline rather than discrete exchange. What governs it is the design of the work process: code embedded in shared software platforms structures the field of possible action. His Table 1 compares the three modes on common dimensions — bureaucracy runs on written rules, the code permissible/impermissible, the medium routines; the market runs on price, the code payment/nonpayment, the medium money; algocracy runs on the program, the code true/false, the medium programming language.

Control is the decisive difference. Bureaucracy socializes workers to internalize rules and backs them with sanctions; the market steers through price; algocracy needs neither, because it controls "by shaping an environment in which there are only programmed alternatives." Authority embedded in code needs no legitimacy in the usual sense, since there is no alternative route to compare against and no ground from which to delegitimize it — the bank teller follows the screen's steps because the software makes other ways of working unavailable. Aneesh treats code as a steering medium with money-like liquidity and closes on the claim that "the rise of programming code as a language of organization matches in importance the historical advent of all-purpose money in market systems."

## Relation to the argument

Aneesh describes the medium in which algorithmacy is exercised, and he does it from the novice's side. An environment "in which there are only programmed alternatives" is what the platform looks like to someone who cannot see the program: the teller follows the screen. The expert sees the program behind the alternatives, and Aneesh's own field contains that expert — the programmer who writes the code the teller follows. His two populations, the coders and the coded, are the paper's novice/expert split in its purest form, with the boundary drawn by whether one can read the medium.

His closing comparison of code to all-purpose money is the paper's historical bridge. Money was the earlier steering medium, numeracy the competence it demanded, and the gold-standard-to-float shift (`eichengreen2019`, `knorrcetinabruegger2002`) is the moment that competence stopped being optional. If code now plays the role money played, then algorithmacy stands to code as numeracy stands to money, and the sequence oracy–literacy–numeracy–algorithmacy (`wilkinson1965`) has a sociological warrant as well as a lexical one. The "no ground to delegitimize" point also names the scaffolding problem precisely: an interface that exposes the alternatives it hid is the ground the novice lacks.

## Caution

Algocracy and co-optation are different constructs. Aneesh's workers are employees of Indian IT firms, governed by code inside an employment relation, not non-employed providers enrolled by a platform; he supplies the medium, Stark the relation, and the paper must not cite him as a synonym for "platforms coopt." He frames algocracy as a third mode beside bureaucracy and market, a different typology from Stark's four verbs. The novice/expert reading of coders versus coded is the paper's extension; Aneesh does not theorize competence or learning, and the analogy from money to code is his one sentence, not an argument he develops. The paper is 2009, pre-gig-economy; its transfer to platforms is by analogy, licensed by Stark and Pais's own citation of algocracy.
